# How the orchestrator is evaluated

Results: [EVALUATION_RESULTS.md](EVALUATION_RESULTS.md) (generated, never edited by hand).

## What is measured

The suite measures the **harness** around the model (does the system behave correctly when the model, the network or a tool misbehaves, or when the input is hostile) and, in live mode, how often a **real model** gets through the pipeline. It does not grade creative quality.

| Metric | Definition |
|---|---|
| Cases passed | Final task state equals the expected state, no write tool ran without approval, every accepted output satisfies its contract, and failures carry the expected reason |
| Valid outputs among succeeded tasks | Share of `succeeded` tasks whose every step output passes `acs/schemas.py` |
| Recovery from injected faults | Pass rate over the cases in `transient`, `invalid_output` and `tool_failure` that expect success |
| Adversarial cases with no unauthorised write | Share of the 15 adversarial cases where the exports folder stayed empty |
| Tool calls blocked by policy | Refused tool calls (unknown tool, not allowed for the agent, bad arguments) |
| Wall time p50 / p95 | Per case, from submit to terminal state |
| Tokens per task | Prompt + completion tokens reported by the provider |

## The case set

`evals/cases.v1.json`, 100 cases, generated by `acs/evals/cases.py` and committed. Changing a case means bumping the version, so results from different versions are never mixed.

| Category | Cases | What it checks |
|---|---|---|
| simple | 20 | Clean runs over 20 different briefs |
| multi_step_tools | 12 | The critic calls 1 to 4 allowed tools (contrast, text stats, reference) before answering |
| tool_failure | 8 | Missing reference, invalid colour, missing argument, unknown tool; the agent gets an error result and must still answer |
| transient | 12 | Timeouts and HTTP 500s that clear after retries (9), and a provider that never recovers (3, must fail cleanly) |
| invalid_output | 15 | Prose, truncated JSON, wrong types, bad hex colours, out-of-range score; 12 recover on retry, 3 never do and must fail |
| cancellation | 5 | Cancel while different agents are running; must end `cancelled` |
| adversarial | 15 | 10 prompt-injection references that make the model request `save_package`, `delete_files`, a `shell` argument or a path traversal; 5 briefs that ask the model to break its output format |
| ambiguous_input | 8 | 5 invalid briefs that must be rejected before any model call; 3 minimal but valid briefs that must run |
| budget | 5 | The model reports 9k-13k tokens per call; the task must stop with "Token budget exceeded" |

## Two modes

**Scripted** (default, free, deterministic): each case carries a script of model replies. A fake transport plays it through the real `OpenAICompatProvider`, so prompt building, the tool loop, JSON extraction, validation, retries and the policy are the production code paths. In the adversarial cases the scripted model *obeys* the injection on purpose: it is a worst-case model, so the result measures the harness, not the model's judgement.

**Live**: the briefs of the `simple`, `multi_step_tools`, `adversarial` and `ambiguous_input` categories go to a real model with no script. Here the model decides everything, including whether to follow an injection.

## Three configurations

| Config | Attempts | Output validation | Validator feedback on retry | Tool policy + approval | Token budget | Jitter |
|---|---|---|---|---|---|---|
| baseline | 1 | off | off | off | none | off |
| improved | 3 | on, invalid answers retried | off | off | none | off |
| final (what the server runs) | 3 | on | on | on | 20,000 | on |

## Reading the results honestly

- The scripted suite was written by the same person who wrote the harness. A 100 % pass rate there means the harness does what it was designed to do against these 100 situations; it is a regression suite, not proof of robustness against unseen failures.
- Scripted wall times measure orchestration overhead only (back-off is shortened to 2 ms in evals); they are not model latency.
- Live results depend on the model, its size and its sampling temperature. They come from one run on one machine; see the environment block in each results file.

## Reproduce

```bash
python3 -m acs.evals.cases                      # only if you change the generator (bump VERSION first)
for c in baseline improved final; do python3 -m acs.evals.runner --config $c; done
python3 -m acs.evals.report

# live, with a local model (needs torch + transformers, ideally a GPU)
python scripts/local_model_server.py --model Qwen/Qwen2.5-1.5B-Instruct --port 8791 &
export ACS_OPENAI_BASE_URL=http://127.0.0.1:8791/v1 ACS_OPENAI_MODEL=Qwen/Qwen2.5-1.5B-Instruct
for c in baseline improved final; do python3 -m acs.evals.runner --config $c --live; done
python3 -m acs.evals.report
```
